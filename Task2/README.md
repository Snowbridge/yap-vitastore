# Task2. Целевой процесс онбординга магазина (BPMN + Automation)

## Резюме

- **Периметр** — перенос номенклатуры купленного магазина: от выгрузки старой базы до корректного ассортимента, цен и остатков на Cloud POS. Монтаж устройств и подключение кассы — параллельная ветка онбординга (Task3).
- **Ручные операции As-Is устранены:** выезд инженера ради выгрузки заменён загрузкой на портал; email и VLOOKUP — оркестратором и AI-сервисом; ночной XML по FTP — событием из 1С:ERP в Cloud POS.
- **AI-маппинг:** точное совпадение по GTIN, нормализация названий YandexGPT, векторный поиск по индексу номенклатуры (pgvector), переранжирование LLM, риск-правила.
- **Точка верификации:** три коридора уверенности (от 95% без флагов — автоматически, 70-95% или риск-флаг — товаровед выбирает из топ-3, меньше 70% — ручной разбор), выборочный аудит 3% автоматики и пробная продажа на кассе до открытия.
- **Эффект:** у человека 20% позиций вместо 80%, ~5 чел.-ч вместо ~16 на магазин, перенос номенклатуры за 1-2 дня вместо 2-3 недель, целевая доля ошибок меньше 1% вместо 15%.

## Допущения

- Средний купленный магазин — 10 000 SKU; поток — 10 магазинов в месяц (Артефакт 4).
- Распределение по коридорам (80% / 15% / 5%) и скорости разбора (~1 000 позиций/ч при выборе из топ-3, ~250 позиций/ч при ручном поиске) — оценки до пилота. Их уточняют на первых магазинах вместе с порогами.
- Cloud POS поддерживает тестовый чек без фискализации и подписку на события ассортимента из 1С — требования к Task3.
- Персональные данные в выгрузке номенклатуры отсутствуют; если выгрузка содержит базу лояльности, её перенос идёт отдельным потоком с учётом 152-ФЗ.
